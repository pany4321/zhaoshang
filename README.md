### 1.2 🏗️ 架构说明：纯前端单页原型

原型**不依赖任何后端**，全部逻辑在浏览器内完成：

- **唯一数据源**：`mock.js` 以 IIFE 挂载到 `window.MOCK`（Node 环境退化为 `global.MOCK`）。页面渲染器从 `MOCK` 读取数据，不发起任何 `fetch` / XHR。
- **固定种子可重现**：`SEED = 20260822` + `mulberry32` 伪随机，每次打开数据完全一致（确定性），便于演示与复现。
- **派生引擎**：`MOCK_ENGINE.enrich / deriveAll / rebuild(raw)` 在加载时一次性计算聚合、图谱、AI 日报、政策兑现等派生结构；前后端分离版复用同一引擎做「服务器数据 → MOCK 形状」的 rebuild。
- **视觉 1:1**：设计系统、DOM 结构、组件（Toast / 抽屉 / 确认框 / 分页 / 骨架屏）、图表配置全部内置，零外部依赖。
- **登录门禁**：`login.js` 以 `admin / admin123` 校验（与后端 `/auth/login` 一致），登录态写入 `localStorage('zs_token' / 'zs_user')`，刷新不丢失；仅作演示门禁，无真实权限隔离。
- **离线可用**：第三方库全部本地内置于 `assets/vendor/`，无需联网或安装依赖。

### 1.6 📊 数据模型

| 实体 | 说明 | 模拟数据量 |
| ------ | ------ | ----------- |
| `Enterprise` 企业 | overview / status / operation / commitments / dynamics / risks / riskScore / riskLevel / shareholders / policies / ai / landMu | 120 家（15 深度建档 + 105 轻量） |
| `RiskEvent` 风险事件 | 三态：待处置 / 已派发 / 已关闭（9 / 31 / 27） | 67 条 |
| `Task` 任务 | 与风险事件联动（待处置→已派发→已关闭）+ 常规任务 | 78 条 |
| `Policy` 政策 | 层级 / 类型 / 部门 / 兑现计划（`POLICY_REDEEM`） | 24 条 |
| `Project` 招商项目 | 6 阶段推进 | 19 个 |
| `Graph` 关系图谱 | 关系网络节点 / 边 | 46 节点 / 117 边 |

- **风险八维加权模型**（`RISK_DIMS`：operation 0.20 / finance 0.15 / judicial 0.15 / credit 0.15 / tender 0.10 / tax 0.10 / perform 0.10 / ip 0.05，合计 = 1）与等级阈值（红 ≥65 / 橙 ≥45 / 黄 ≥25 / 蓝）在 `mock.js` 固化。
- **派生量**：综合风险指数 = Σ(weight × risks[dim])；到位资金 = 协议额 × 进度；兑现率来自 `POLICY_REDEEM`。
- **一致性**：所有汇总 / 明细由同一份种子数据推导，天然对账；`tools/check_invariants.js` 校验风险三态与任务映射不变式。

### 1.8 ⚠️ 说明

- 本原型为**演示用途**，数据均为模拟生成（固定种子），不代表任何真实企业。
- AI 智能体使用**预置脚本回复**（`generateReply` 确定性话术），未对接真实大模型；智能体话术中的「九维」为口语口径，实际风险模型为**八维**（见 `mock.js` 的 `RISK_DIMS`）。
- 纯前端**无后端、无鉴权、无持久化落库**：所有交互在内存中，刷新后回到种子初始态（仅登录态由 localStorage 保留）。
- 风险事件派发 / 任务办结等「闭环」为前端内存态演示，不落库；如需真实工作流闭环与落库，请使用前后端分离部署版（见第二部分）。
- 第三方库全部本地内置，**完全离线可用**，无需联网或安装依赖。

### 2.2 🏗️ 架构说明：demo 引擎复刻

前端**不重新实现页面**，而是直接复用 demo 的页面渲染引擎（`web/public/engine/`），
Vue 壳只负责：登录鉴权、路由托管、数据下发与工作流动作持久化。

```
登录 → /api/bootstrap 一次性下发全部实体（企业/事件/项目/任务/政策/字典）
     → 适配层 (src/engine/adapter.ts) 映射为 demo 数据形状
     → MOCK_ENGINE.rebuild() 重算全部派生结构（聚合/图谱/AI日报/政策兑现…）
     → 引擎页面渲染器按 demo 原样渲染到 #content
```

- **视觉 1:1**：样式表、DOM 结构、组件（Toast/抽屉/确认框/分页/骨架屏）、
  图表配置全部来自 demo 原文件。
- **数据实时**：页面展示的每个数字都由服务器实体推导（与明细天然对账）。
- **工作流闭环持久化**：风险派发 → 服务端建任务；任务完成 → 服务端办结并联动
  事件闭环；新建项目/企业建档、项目进展备注、政策入库、AI 会话历史均同步后端。
- **离线降级**：`/api/bootstrap` 不可用时自动回退内置种子数据（与 demo 完全一致）。

## 三、面向政府客户交付：生产化功能完善指引

> **定位**：本仓库交付的是「高保真原型 + 可运行演示基线」。它验证了业务模型、页面交互与核心闭环的可行性，但**不构成可直接交付政府客户上线的系统**。本章按能力域列出从演示基线到生产交付需要重点完善的功能，供立项报价、方案编写与开发排期参考。

### 能力域总览

| 能力域 | 当前原型状态 | 生产交付要求 | 优先级 |
| --- | --- | --- | --- |
| 数据接入与治理 | 11 类数据源为展示项，全部数据由 fixtures 生成 | 真实政务数据源对接 + 采集调度 + 质量监控 | ★★★ |
| 身份认证与权限 | 本地 JWT，角色字段存在但无接口级拦截 | 政务统一认证 SSO + 功能/数据双层 RBAC + 审计 | ★★★ |
| AI 能力 | 预脚本确定性话术 | 合规大模型接入 + RAG + 证据链 + 人工复核 | ★★★ |
| 业务闭环 | 风险派发→任务→办结已打通（含演示简化） | 责任到人、督办升级、审核销号、审批流 | ★★★ |
| 消息通知 | 无，依赖用户主动刷新 | 站内信 + 短信/政务即时通推送 | ★★ |
| 数据库与部署 | SQLite 单文件 + 单实例 | 政务云数据库 + 集群 + 信创适配 | ★★ |
| 安全合规 | 演示凭据、无等保动作 | 等保三级测评 + 国密 + 渗透整改 | ★★★（一票否决） |
| 可观测性 | health 接口 + server.log | 结构化日志、监控告警、运维交付物 | ★★ |
| 质量保障 | 冒烟/对账/接口回归（tools/） | 单元测试、契约测试、UAT 验收体系 | ★★ |

### 3.1 🗄️ 数据接入与数据治理（★★★）

智慧监管的根基是真实数据。当前系统的一切数字由演示数据推导，交付前必须建成**数据接入层**：

- **数据源对接**：与市监（工商登记）、税务、人社、法院、公共资源交易、知识产权、生态环境、应急管理、住建等委办局系统建立接口，明确每类的交换方式（库表交换 / 接口调用 / 文件交换）与更新频率（T+0 / T+1）。优先对接省市级**数据共享交换平台**，而非逐一点对点集成。
- **采集与加工**：定时调度、增量识别、清洗转换（统一社会信用代码 / 行政区划 / 行业主数据的标准化对齐）、失败重试与每日对账。
- **数据质量监控**：把驾驶舱的「数据资源接入」卡升级为真实功能——完整率、及时率、准确率指标看板，异常数据生成人工核查任务并进入工作流。
- **主数据治理**：企业主档案以统一社会信用代码为主键进行多源归一，处理一企多名、注销迁出等生命周期事件。

### 3.2 🔐 统一身份认证与权限体系（★★★）

现状：`server/src/routes/auth.ts` 提供本地 JWT 登录，用户表有 `role` 字段，但**所有业务接口未做角色拦截**，前端也未按角色显隐功能。

- **统一认证对接**：接入省级政务统一身份认证 / 政务即时通讯工作台（如浙政钉、赣政通）实现单点登录，同步组织架构与人员；本地账号体系保留为离线兜底。
- **功能权限（RBAC）**：定义角色-菜单-按钮-接口的权限矩阵（局领导 / 招商专员 / 风险管理员 / 系统管理员），在 Fastify 路由 `preHandler` 统一拦截，前端导航与操作按钮按角色渲染。
- **数据权限**：区县、部门、企业范围的数据行级隔离（专员只看本辖区），列表与聚合口径同步生效。
- **操作审计**：登录、派发、办结、政策推送、数据导出等关键操作全量留痕（操作人 / 时间 / IP / 对象 / 结果），支持审计检索与导出，日志留存不少于 6 个月（网络安全法要求）。
- **账号安全**：密码复杂度与有效期策略、连续失败锁定、会话超时、敏感操作二次确认。

### 3.3 🤖 AI 能力真实化（★★★）

现状：四个智能体与企业画像 AI 研判均为**预脚本确定性回复**（`aidemo.js` / `profile.js`），价值在于交互形态与可解释结构，不具备真实分析能力。

- **模型接入**：接入政务云私有化部署的大模型服务（或经审批的公有云模型），建设统一 LLM 网关，管理鉴权、限流、超时与成本；**现有预脚本话术天然就是降级预案**——模型不可用时回退规则模板，页面不空转。
- **政策知识库 RAG**：真实政策库向量化检索，支撑政策匹配推荐与智能体问答给出可溯源的条款引用；政策库从 24 条演示数据扩展为持续维护的真实库。
- **可解释与证据链**：AI 结论必须引用具体数据来源（现有「数据来源 / 置信度」面板结构可直接复用），扩展为逐条结论挂接证据字段。
- **人机边界**：AI 输出标注「辅助研判」性质，高风险结论经人工复核后方可进入派发流程；建立输出内容安全过滤与违规兜底。

### 3.4 🔁 业务闭环深化（★★★）

风险「派发 → 任务 → 办结 → 事件关闭」的闭环前后端已打通，但包含演示性简化：

- **任务指派到人**：现在任务按账号轮换分配；生产版需按辖区/行业路由到具体责任人，支持转办、协办。
- **督办与升级**：任务超期自动升级提醒（专员→科长→分管领导），督办记录留痕。
- **核查销号**：办结后增加复核环节，复核不通过驳回重办，防止虚假闭环。
- **政策兑现全流程**：政策详情抽屉的在线申报/批量推送目前为预留能力——需补齐在线申报表单、材料上传、多级审核流、兑现结果与财政支付系统对接、资金绩效跟踪。
- **项目管理扩展**：当前为「一企一项目」唯一约束（`Project.enterpriseId @unique`），需支持一企多项目；签约、立项等关键节点接入审批流与领导签批；协议文本与附件管理。
- **企业侧门户**：需求说明书规划的「企业侧服务门户」（诉求提交、政策申报、进度查询）为零起点新模块。

### 3.5 📣 消息通知与协同（★★）

当前系统没有任何主动通知，所有事件依赖用户登录后自行查看。需补齐：站内消息中心；对接短信网关与政务即时通讯（政务钉钉 / 政务微信）推送；预警触发、任务指派、超期提醒、政策上新等事件的个性化订阅配置。

### 3.6 🏗️ 数据库与部署架构（★★）

现状：SQLite 单文件 + 单实例 Fastify，满足演示与单机 POC，不满足生产。

- **数据库**：迁移到政务云认可的数据库（PostgreSQL / 达梦 / 人大金仓）。数据层已由 Prisma 隔离，主要工作是方言适配与索引优化；配套定时全量 + 增量备份与异地容灾演练。
- **部署形态**：政务外网与互联网分区部署；前端静态资源 + API 多实例集群 + 反向代理；容器化交付（K8s 或政务云容器平台），支持灰度发布与回滚。
- **信创适配**：国产 CPU（鲲鹏 / 飞腾 / 海光）+ 国产操作系统（麒麟 / 统信）+ 国产数据库 / 中间件的适配验证。政府项目招标的常见硬性要求，**应在一期选型时即纳入验证**，避免后期返工。
- **容量验证**：企业规模从演示的 120 家扩展到全市数千至数万家时，列表分页、聚合指标、图谱计算的响应时间需实测并优化。

### 3.7 🛡️ 安全合规与等保测评（★★★，一票否决项）

- **等保定级备案与测评**：政务信息系统通常要求**等保三级**，涉及物理环境、通信网络、区域边界、计算环境、管理中心五个层面，测评周期长，应与开发并行启动。
- **密码应用**：全站 HTTPS；企业法人、联系人等敏感字段加密存储；按客户要求支持国密算法（SM2 / SM3 / SM4）。
- **漏洞治理**：上线前渗透测试与漏洞扫描整改；建立依赖组件漏洞巡检机制。
- **数据出域管控**：系统部署于政务外网时严禁数据出域；互联网环境（含本仓库的在线 demo）只允许演示数据，不得接入任何真实企业数据。

### 3.8 📈 可观测性与运维交付（★★）

- 结构化日志采集与检索、接口错误率 / 时延监控告警、慢 SQL 治理；现有 `/api/health` 扩展为就绪 / 存活探针供容器平台编排。
- 交付物清单：部署手册、数据字典、运维手册、应急预案，以及面向客户运维团队的培训。

### 3.9 ✅ 质量保障与验收（★★）

- 为核心业务逻辑（风险加权评分、任务-事件闭环守恒、权限拦截、口径对账）补充单元测试；为对外接口建立契约测试。
- 本仓库 `tools/` 下的冒烟与对账脚本已纳入 CI（`npm test`），可直接作为验收自动化基线继续扩展。
- 按需求说明书（V5.0 深化版）组织逐模块 UAT；注意**演示口径与验收口径分离**——UAT 一律使用真实接入数据。
