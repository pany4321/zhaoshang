## 3. 统一需求原则

1. **用户视角优先**：先描述用户目标、工作任务、操作过程和业务结果，再描述系统实现。
2. **业务功能优先**：用户看到的是企业、项目、风险、政策、任务和决策功能；AI属于这些功能的智能增强能力。V3.1明确提出业务系统是主体、AI是智能化运行能力。fileciteturn1file1L61-L98
3. **数据贯通**：企业主数据统一，页面指标同源，业务对象之间可追溯、可对账。V4.0强调所有页面指标由同一企业库实时聚合推导。fileciteturn2file4L418-L428
4. **结果必须落到业务对象**：AI输出应转化为风险事件、任务、企业标签、项目建议、服务事项或报告，并回到原有业务流程执行。fileciteturn2file6L696-L723
5. **人机协同**：AI负责理解、分析、判断、编排和辅助执行；重要监管事项由工作人员作出最终决定。fileciteturn2file0L15-L44
6. **权限一致**：AI调用业务数据必须继承用户权限，不能通过AI绕过业务系统的数据权限。
7. **分阶段建设**：先解决企业家底、风险和项目管理，再扩展画像、政策服务、产业图谱和AI智能体。V4.0已给出三阶段落地路径。fileciteturn2file1L141-L163

# 第一卷 项目总览与用户需求

# 一、项目概述

## 1.1 建设背景

地方政府招商工作需要从“项目引进”进一步延伸到企业落地、建设、投产、达产及持续经营。传统模式中，项目、企业经营、纳税、招投标、知识产权、司法、信用、政策和服务信息分散在不同部门和系统，工作人员需要人工查询、电话沟通和维护表格，导致信息不完整、变化发现滞后、招商承诺难以持续跟踪、风险处置和企业服务难以形成闭环。V3.1对此进行了系统归纳。fileciteturn1file7L543-L558

## 1.2 建设定位

平台定位为：

> **以企业为核心、以数据为基础、以业务流程为主线、以AI为智能化能力的招商企业服务与智慧监管平台。**

核心不是“招商系统+AI模块”，而是将企业管理、招商项目、企业画像、经营分析、风险监管、企业服务、政策服务、产业分析和领导决策统一起来。V4.0将平台定位为AI原生、企业核心、数据驱动的监管与服务一体化平台。fileciteturn1file9L645-L662

# 二、用户角色与核心诉求

## 2.1 主管领导

### 用户目标

主管领导不需要浏览大量企业明细，而需要快速回答：

- 全市招商企业总体运行情况如何？
- 哪些企业最值得关注？
- 哪些项目推进滞后？
- 哪些风险正在上升？
- 招商目标完成得怎么样？
- 企业服务和政策兑现效果如何？
- 今天有哪些事项需要领导关注？

V3.1明确提出主管领导需要“一屏掌握总体情况、重点企业、重点项目、重点产业、重点风险和异常变化”。fileciteturn1file8L603-L617

### 系统提供

- 招商驾驶舱；
- 风险态势与重点风险；
- 项目阶段与重点项目；
- 区县及产业对标；
- 政策兑现情况；
- AI每日运行综述；
- 今日行动项；
- 自然语言问数与专题分析；
- AI报告生成。

## 2.2 招商部门领导

### 用户目标

围绕“招商任务—项目推进—企业落地—运营质量—招商绩效”开展管理。重点关注项目来源、洽谈、签约、落地、实际到资、建设进度、达产情况、企业营收纳税、重点产业、高潜企业和风险企业。

### 系统提供

- 项目全生命周期视图；
- 项目阶段漏斗；
- 招商目标完成度；
- 招商人员工作和绩效分析；
- 企业质量评价；
- 重点项目和风险项目清单；
- AI招商分析与跟进建议。

## 2.3 招商专员

### 用户目标

招商专员的核心不是“看大屏”，而是“今天该做什么、企业最近发生了什么、项目下一步怎么办”。V4.0将其主要入口定义为“我的工作台、企业画像、项目详情、政策服务”。fileciteturn2file4L432-L444

### 系统提供

- 我的任务；
- 负责企业；
- 项目跟进；
- 企业走访与沟通记录；
- 风险处置；
- 企业服务；
- 政策推送；
- AI今日工作助手；
- AI企业分析、项目分析和风险分析。

## 2.4 产业主管、风险管理人员、数据管理员及协同人员

V3.1规划了更完整的角色体系，包括产业主管、风险管理人员、数据管理员、部门协同人员以及企业用户等，并要求按组织、区县、园区、部门、招商专员和企业本人等维度控制数据范围。fileciteturn2file0L48-L76

新版要求保留该能力，但用户界面仍以核心三类政府用户为主，其他角色通过权限体系进入对应业务功能。

# 三、用户工作方式总体设计

## 3.1 从“查数据”转向“看变化”

系统应优先呈现变化、异常、待办和需要处理的事项，而不是单纯提供数据库式查询。AI可以持续分析数据变化，主动形成事件、摘要和行动项。V4.0明确提出“信息找人”。fileciteturn1file9L664-L668

## 3.2 从“看页面”转向“完成工作”

用户在企业、项目、风险、政策等页面看到分析结果后，应能够继续完成下一步业务动作，例如：

`AI分析 → 生成任务 → 指派人员 → 处理 → 反馈 → 复核`

## 3.3 从“多个系统分别使用”转向“一个业务工作空间”

企业是统一主线。用户可以从驾驶舱进入企业，从企业进入风险、项目、政策和任务，再返回企业形成完整上下文。

# 四、总体用户价值

平台最终形成“五个一”：一个企业数据库、一套企业数字档案、一张产业关系图谱、一个风险预警中心、一个招商智能驾驶舱；同时形成AI看企业、AI找风险、AI做招商、AI帮政府服务企业等能力。fileciteturn1file9L651-L662
# 第二卷 核心业务功能需求

# 一、招商驾驶舱

## 1.1 用户目标

主管领导进入系统后，应无需逐项查询即可了解全市招商企业、项目、产业、风险和服务态势。V4.0已将驾驶舱设计为全市/县区视角联动的核心入口。

## 1.2 核心功能

- 组织视角切换：全市、县区；
- 企业总数、重点企业、新增企业、风险企业等KPI；
- 营收、纳税、投资、就业等总体趋势；
- 重点企业TOP；
- 招商目标完成度；
- 项目六阶段漏斗；
- 区县招商业绩；
- 重大项目TOP；
- 区县企业分布；
- 产业分布；
- 风险等级和风险处置效率；
- 政策兑现；
- 数据资源接入情况；
- AI今日运行综述与行动项。

驾驶舱中的统计结果必须支持下钻到具体企业、项目或风险事件，而不是只提供静态图表。

# 二、企业档案库

## 2.1 企业统一档案

以统一社会信用代码为核心索引，形成一企一档。至少覆盖：企业基本信息、经营指标、招商信息、风险、关系、政策、动态和AI研判。V3.1明确企业信用数据库由现有专业系统提供，本平台不重复建设。fileciteturn1file8L585-L591

## 2.2 企业名录

支持按企业名称、法人、统一社会信用代码、风险等级、行业、区县、企业规模等条件查询和筛选，并支持排序、分页、导出。

# 三、企业360°画像

企业画像是平台最核心的业务对象，建议统一形成六层结构：

1. **企业概况**：基本工商信息、规模、经营指标、招商承诺；
2. **经营状态**：经营/信用状态、企业动态时间轴；
3. **经营趋势**：营收、纳税、投资等趋势；
4. **关系网络**：股东、投资及相关关系；
5. **企业风险**：风险维度、综合评分、风险事件；
6. **AI综合研判**：企业优势、经营趋势、履约情况、风险、行业环境和服务建议。

V4.0已按上述六层实现企业画像结构。fileciteturn1file0L69-L75

## 3.1 企业动态

将工商变更、招商、经营、招投标、知识产权、信用、司法等变化形成统一时间轴。重要变化可由AI生成“近期AI发现”。

## 3.2 企业经营分析

核心指标包括营收、利润、纳税、投资、员工、研发、产值、出口、用电和用工等。系统支持本期值、同比、环比、行业排名、地区排名和趋势分析。

## 3.3 招商履约

把招商协议中的注册资本、实际投资、营收、纳税、就业、厂房等承诺转成结构化指标，持续比较“承诺—实际—完成率—时间进度—偏差”。

# 四、风险预警与处置

## 4.1 风险模型

V4.0当前采用八维加权模型，环保风险作为预留维度：经营20%、财务15%、司法15%、信用15%、招投标10%、税务10%、招商履约10%、知识产权5%。综合指数归一化为0—100。fileciteturn1file0L297-L329

风险等级：重大、较高、一般、关注四级。风险评分用于政府内部监管资源配置和辅助研判，不作为行政处罚、市场准入限制等行政决定的唯一依据。

## 4.2 风险事件

支持：

- 风险事件发现；
- 风险依据展示；
- AI研判；
- 派发；
- 处置记录；
- 关闭；
- 复核；
- 查询和导出。

## 4.3 风险闭环

`风险发现 → 一键派发 → 专员处置 → 事件关闭 → 驾驶舱闭环率更新`。V4.0已明确风险事件和任务状态联动。fileciteturn2file4L424-L428

# 五、招商项目全生命周期

项目六阶段：

1. 线索对接；
2. 深度洽谈；
3. 签约落地；
4. 建设推进；
5. 投产运营；
6. 达产评价。

每个阶段至少沉淀时间节点、责任人、投资金额、关键事项、进展记录和风险。项目管理必须解决“签约即终点”的问题。

## 5.1 项目创建与推进

支持项目新建、企业关联、阶段推进、进展记录、关键节点、招商承诺、对接记录和跟进任务。

## 5.2 AI招商推荐

根据候选企业、产业匹配、企业实力、投资强度、就业和税收等维度形成候选招商企业，并提供推荐理由。AI推荐结果确认后，应转化为企业和项目业务对象，而不是停留在聊天文本中。

# 六、政策服务

## 6.1 政策库

形成政策统一目录、分类、详情和适用范围。

## 6.2 企业政策匹配

根据企业行业、规模、发展阶段和标签自动匹配政策，支持从企业画像直接进入政策服务。

## 6.3 政策惠企闭环

`AI政策匹配 → 推送企业 → 申报辅导任务 → 工作台办理 → 结果反馈`。这是V4.0明确的三条业务主线之一。fileciteturn2file4L424-L428

# 七、企业服务

企业诉求覆盖项目建设、用地、用工、融资、人才、政策咨询、证照、环保、水电气和上下游合作等。

处理过程：`企业提交 → AI识别 → 自动分类 → 智能分派 → 部门办理 → 企业反馈 → 评价 → 关闭`。

# 八、产业关系与招商谋划

建立企业、股东、实际控制人、投资、项目、招投标及产业链关系，分析龙头企业、配套企业、产业链缺口和补链招商方向。V3.1将企业—项目—招标人—代理机构—联合体—竞争企业等关系网络作为重要分析对象。fileciteturn1file2L153-L169

# 九、招商绩效

招商绩效不只统计签约数量，而综合考虑招商数量、招商质量、落地质量和运营质量，并进一步观察企业营收、纳税、就业、投资和达产情况。

# 十、跨页面业务体验

系统应支持：

- 全局搜索；
- 从KPI下钻；
- 从图表进入企业/项目/风险；
- 返回时保持上下文；
- 筛选条件联动；
- CSV导出；
- 统一加载、空状态、确认和消息提示。

V4.0已把这些能力作为统一的全局交互要求。
# 第三卷 AI融合与智能化需求

# 一、AI总体定位

## 1.1 核心原则

> **业务系统是主体，AI是智能化运行能力；业务功能负责执行，AI负责理解、分析、判断、编排和辅助执行。**

V3.1明确要求不建设与招商业务系统割裂的独立AI智能体平台；用户不需要理解Agent技术概念，而应在企业、项目、风险、政策等业务上下文中自然获得AI能力。fileciteturn1file1L61-L98

## 1.2 用户看到的AI

AI不作为新的业务入口，而主要表现为：

- AI分析企业；
- AI分析项目；
- AI研判风险；
- AI匹配政策；
- AI推荐招商对象；
- AI生成任务；
- AI生成报告；
- AI每日摘要；
- AI主动提醒。

# 二、AI业务能力矩阵

| 业务场景 | 用户原有功能 | AI增强能力 | 输出结果 |
|---|---|---|---|
| 企业管理 | 企业档案 | 企业洞察、动态分析 | 企业研判、标签、摘要 |
| 项目管理 | 项目跟进 | 项目研判、延期分析 | 跟进建议、任务 |
| 风险监管 | 风险事件 | 风险发现、解释、建议 | 风险事件、处置建议 |
| 政策服务 | 政策库 | 企业政策匹配 | 服务事项、推送 |
| 产业招商 | 产业分析 | 企业推荐、产业链分析 | 招商候选、招商建议 |
| 领导决策 | 驾驶舱 | 问数、专题分析、日报 | 摘要、图表、报告 |
| 报告中心 | 报告 | AI生成 | 可编辑、可审批报告 |

# 三、AI与业务系统的结合方式

## 3.1 AI不直接访问数据库

采用：

`AI → 业务服务 → 数据服务`

而不是：

`AI → 数据库`

V3.1明确该方式用于保证业务规则、数据权限和审计体系统一。fileciteturn2file6L608-L668

## 3.2 AI调用业务能力

业务系统向AI提供标准工具，例如企业查询、经营分析、税务查询、招投标查询、信用查询、风险查询、项目查询、政策匹配、任务创建和报告生成等。

这些工具本质上是**业务系统能力的AI可调用接口**。Agent负责理解任务、选择业务能力、调用工具、综合分析、输出结果，并在授权范围内发起业务动作。fileciteturn2file6L636-L668

# 四、四类核心AI智能体

## 4.1 企业洞察智能体——AI看企业

### 用户入口
企业360°画像中的“AI综合研判”。

### 主要工作
综合企业基本信息、经营、纳税、招投标、知识产权、信用、司法、招商履约等数据，形成企业经营概况、成长性、行业地位、创新能力、市场能力、履约情况、风险和服务建议。

### 用户结果
不是只给一段话，而是形成可查看的数据依据、分析结论、风险事项和报告。

## 4.2 风险研判智能体——AI找风险

### 用户入口
风险中心、企业画像风险页、AI主动事件。

### 主要工作
持续分析经营、财务、司法、信用、招投标、税务、招商履约和知识产权变化，识别潜在风险，并解释风险依据。

### 结果
风险事件、风险等级建议、风险依据、可能原因和处置建议。

## 4.3 招商谋划智能体——AI做招商

### 用户入口
招商项目页、产业分析页。

### 主要工作
结合产业链缺口、候选企业画像、投资强度、产业契合度、企业实力、就业和税收贡献等因素形成招商推荐。

### 结果
候选企业、推荐理由、评分、招商方向以及“纳入招商项目”的业务动作。

## 4.4 企业服务智能体——AI帮政府服务企业

### 用户入口
企业服务、政策服务、企业画像。

### 主要工作
识别企业诉求、匹配责任部门、匹配政策和历史案例，并生成服务任务。

# 五、AI主动业务事件

## 5.1 从“用户提问”到“系统主动发现”

系统可根据数据变化或业务事件自动触发AI分析。例如营收下降、员工减少、纳税下降、项目投资滞后等组合变化可触发综合研判。

## 5.2 AI事件必须进入业务系统

流程：

`数据变化 → AI识别 → AI分析 → 业务事件 → 规则判断 → 预警 → 推送责任人 → 业务任务 → 处置反馈 → AI复核`

AI事件不能停留在独立的Agent控制台。

# 六、AI结果可信与责任边界

## 6.1 数据证据链

重要AI结论应能够展示：

- 数据来源；
- 数据时间；
- 数据指标；
- 计算逻辑；
- 风险规则；
- 相关事件。

## 6.2 权限继承

用户没有权限查看的数据，AI也不得通过工具调用获取。

## 6.3 人机协同

涉及重要监管事项时，AI只能提出建议，不替代工作人员作出行政决定。

## 6.4 AI审计

记录用户、AI Agent、模型、Prompt、工具调用、数据访问、AI结论、人工修改和最终执行结果。V3.1已将这些列为AI审计要求。fileciteturn2file0L15-L44

# 七、AI报告能力

AI报告必须嵌入业务页面。用户点击“AI生成报告”后，系统基于当前业务数据生成企业分析、项目分析、风险报告、产业报告、招商月报或领导汇报材料；生成后进入原有报告中心，可继续人工修改和审批。fileciteturn2file8L834-L852

# 八、AI交互原则

1. 页面即AI入口；
2. 数据即AI输入；
3. 事件即AI触发器；
4. AI结果即业务对象；
5. 执行必须回到业务系统；
6. 用户无需进入独立Agent控制台；
7. AI结论必须有依据、可追溯、可审计。

# 一、数据体系

## 1.1 数据总体原则

平台以企业主数据为核心，不重复建设已有专业系统的数据资源。企业信用数据由现有企业信用数据库提供，本平台通过标准接口或数据交换方式获取。fileciteturn1file8L585-L591

# 三、AI需求验收框架

## 3.1 AI嵌入性

验收：用户在企业、项目、风险、政策、产业和驾驶舱等业务页面能够直接获得对应AI能力，不要求另建独立Agent业务入口。

## 3.2 AI数据权限

验收：AI调用数据必须继承当前用户权限，不能通过工具调用越权访问。

## 3.3 AI证据链

验收：重要结论能够查看数据来源、时间、指标、计算逻辑、规则和相关事件。

## 3.4 AI业务闭环

验收：AI生成的风险、任务、服务事项、项目建议和报告能够进入对应业务模块继续处理。V3.1明确要求AI结果必须回到原有业务系统执行。fileciteturn2file6L704-L723

## 3.5 AI人工确认

验收：涉及重要监管事项时，AI不能直接作出行政决定；人工确认、修改和最终执行结果必须留痕。

# 四、三大业务闭环验收

## 4.1 风险处置闭环

`风险发现 → 派发 → 任务生成 → 专员处置 → 任务完成 → 风险关闭 → 驾驶舱更新`

要求风险事件和任务状态双向关联，避免出现“事件已关闭但任务未完成”或相反情况。

## 4.2 项目推进闭环

`项目创建 → 阶段推进 → 跟进任务 → 节点记录 → 达产评价`

要求项目每个阶段能够记录时间、责任人、进展和关键事项。

## 4.3 政策惠企闭环

`政策匹配 → 企业触达 → 申报辅导 → 办理 → 结果反馈`

# 五、数据验收

1. 企业唯一主键明确；
2. 页面统计与企业明细可以对账；
3. 区县合计与全市口径一致；
4. 风险企业数量与风险等级分布一致；
5. 风险事件与任务数量、状态一致；
6. 项目阶段数量与项目清单一致；
7. 数据来源和更新时间可追溯；
8. 外部专业系统数据不重复建设。

# 六、权限与安全验收

1. 不同角色只能看到授权功能；
2. 不同组织只能访问授权范围的数据；
3. AI不允许绕过用户权限；
4. 敏感数据访问可审计；
5. 关键操作留痕；
6. 接口具备身份鉴别和访问控制；
7. 数据传输和存储安全措施符合建设要求；
8. AI工具调用可审计。

# 七、用户体验验收

- 核心页面入口清晰；
- 驾驶舱可下钻；
- 企业画像信息层次清晰；
- 项目、风险、政策和任务可以相互跳转；
- 搜索、筛选、分页、导出统一；
- 加载态、空状态和异常提示明确；
- 中文输入法组合输入不被异常刷新打断；
- 重要操作有确认机制。

# 八、最终产品形态

最终产品不是“多个业务模块+一个AI聊天窗口”，而应形成：

> **一个企业中心 + 一个领导驾驶舱 + 一个招商工作台 + 一个风险预警中心 + 一个项目全生命周期管理体系 + 一个政策与企业服务体系 + 一张产业关系图谱 + 一套无处不在的AI智能服务能力。**

其核心逻辑是：

`企业进入平台 → 信息归集 → 形成画像 → 持续监测 → 发现变化 → AI分析 → 形成事件/建议 → 进入业务任务 → 人员处置 → 结果反馈 → AI复盘 → 领导决策`

这也是两版说明书共同指向的产品形态：以企业为核心、以业务为主体、以数据为基础、以AI为智能引擎，实现招商、服务、监管和风险预警全过程智能化。fileciteturn2file9L959-L981
