# 数据口径说明

> 适用系统：《招商企业服务与智慧监管平台》单体部署版
> 文档性质：交付附件。界面按需求不标注数据来源，本文件为**唯一口径依据**，对外引用数字前必须先看本文。
> 最后核对：2026-10-21（本次新增第六章「招商智能推荐」；修订第七章第 1/2 条旧样本残留、第九章更新机制表述）

---

## 一、总原则

系统内数据按可信度分为四层。**越靠下的层越不能当作"统计事实"对外发布。**

| 层级 | 名称 | 性质 | 可否对外引用 |
|---|---|---|---|
| A | 事实数据 | 数据仓库直接取回，未加工 | ✅ 可，注明统计口径与时点 |
| B | 聚合计算值 | A 类数据按固定规则汇总 | ✅ 可，需说明"基于 N 家样本" |
| C | 规则推导值 | 由注册资本等参数按公式推算 | ⚠️ 仅供内部研判，**不得作为对外统计口径** |
| D | 业务演示数据 | 为跑通业务流程生成 | ❌ 不可对外引用 |

## 三、B 类：聚合计算值

由 A 类数据 reduce 得出，规则固定，可复核。

| 指标 | 计算规则 |
|---|---|
| 企业总数 | 样本内企业计数（88，随同步变动） |
| 区县分布 | 按 `districtId` 分组计数（区县归属为 A 类原始字段，真实） |
| 产业分布 | 按 `industryId` 分组计数——⚠️ **`industryId` 为招商产业口径，属 C 类规则推导**（按企业名称+经营范围关键词归并到 12 个重点产业），**不是国标统计口径**，不得作为统计事实对外引用 |
| 国标行业分布 | 按 `nationalIndustry` / `nationalIndustryL1` 分组计数——**A 类事实数据**（来源 `company_industry`，2017 国民经济行业分类，官方公示），可对外引用 |
| 风险企业数 | 风险等级为红/橙/黄的企业计数（口径随页面不同） |
| 专利数/商标数/招投标次数 | 对 A 类明细求和 |
| 司法案件数 | 对 A 类案件计数 |

**可信度：区县/国标行业分布为高（A 类）；招商产业分布为「仅供招商汇报」，对外引用须改用国标口径。** 前提是承认样本是定向选取的。

> **两套行业口径并存（2026-10-21 新增）**
> 每家企业同时存两套行业字段：
> - `industryId` → 招商视角 12 个重点产业（如「石油化工与能源」），由 `tools/gen_real_fixtures.py` 的 `INDUSTRY_RULES` 关键词表推导，属 C 类。驾驶舱「产业分布结构」用此口径。
> - `nationalIndustryL1 / nationalIndustry / nationalIndustryL3` → 2017 国标一级/二级/三级分类（如「建筑业 / 房屋建筑业 / 住宅房屋建筑」），来自 Doris `company_industry` 表官方公示数据，属 A 类。覆盖率 **88/88（100%）**（2026-10-22 补齐此前缺失的 9 家记录），可用于对上报送与外部核验。
>
> 两者差异显著（例：规则推导「石油化工与能源 25 家」为最大产业，国标口径下「建筑业 19 家」才是最大；「庆阳鼎辅石油工程服务」因名称含「石油」被归入石油化工，真实国标为「租赁业」）。**任何对外口径引用前必须先确认用的是哪一套。**

| # | 卡片 | 计算口径 | 数据类别 | 点击下钻套用的筛选 |
|---|---|---|---|---|

| 3 | 本月新增 | 成立日期落在当月 | A 类字段（`found`） | 成立时间 = 本月新成立 |
| 4 | 本年新增 | 成立日期落在当年 | A 类字段（`found`） | 成立时间 = 本年新成立 |
| 5 | 风险企业 | 风险等级 ∈ {重大风险, 较高风险}（red + orange） | B 类 | 风险等级 = 重大 + 较高 |
| 6 | 总营收 | Σ 年报营业收入 | A 类求和 | 不提供下钻（求和类无对应行级筛选） |

**一致性约束**：1–5 号卡片点击下钻后，企业概况页「筛选企业数」必须等于该卡片数值；切换辖区（全市/某区县）后同样成立。

**2026-10-23 修正的三处口径偏差**

| 卡片 | 原实现 | 问题 | 修正后 |
|---|---|---|---|
| 重点企业 | 按 `scale='大型企业'` 推断 → 4 家 | 与真实「重点招商企业」标记不符 | 按 `isKey` → **11 家** |
| 本月新增 / 本年新增 | `signDaysAgo` 随机 1~180 天；`(id×37)%100<18` → 19 / 30 家 | 与真实时间无关，且清单页无法按同口径筛出 | 按工商登记成立日期 → **0 / 0 家**（88 家样本最新成立于 2024 年，2025–2026 无新注册） |

## 四、C 类：规则推导值

### 已升级为真实值的字段（2026-10-21）

以下字段现在**全部取自工商年报公示值**，不再是推导值：

| 字段 | 来源 |
|---|---|
| 营业收入 | `annual_report_asset.business_income` |
| 纳税总额 | `annual_report_asset.tax_amount` |
| 资产总额 | `annual_report_asset.total_amount` |
| 净利润 | `annual_report_asset.profit_amount` |

样本 88 家企业 **全部**有这四项真实值（`finYear` 字段记录所属年份；无真实年报财务的企业已从样本中剔除，生成脚本内置硬断言，凑数会导致构建直接失败）。

### 仍为推导值的字段

| 字段 | 公式 | 说明 |
|---|---|---|
| 固定资产投资（万元） | `注册资本 × (0.80 ~ 1.50)` | 年报无此口径 |
| 带动就业（人） | `营收 ÷ (40 ~ 76)` | 年报从业人数为文本，未清洗接入 |
| 占地（亩） | `固投 ÷ (230 ~ 400)` | 派生值 |
| 亩均税收（万元/亩） | `纳税 ÷ 占地` | 派生值 |

### 必须注意

- 样本总营收 **91.7 亿**、纳税 **6.80 亿** 为**真实年报值之和**，可对外引用，但须注明"基于 88 家样本企业"。纳税合计不含任何推导值：39 家年报公示纳税为 0，1 家未公示纳税额的按 0 计入（非推导）。
- 固投 **、就业、亩均税收仍为推导值**，不得作为统计口径。
- 风险指数（八维加权）是模型设定，不是监管认定结论。
- 年报数据为**企业自主申报**，存在个体偏差（如营收 330 万而资产也是 330 万这类填报简化）。

## 六、招商智能推荐（2026-10-21 新增）

> 对应「项目管理」页的「AI 智能推荐」功能。本节说明其候选数据来源、模型职责边界，以及「确认纳入」后哪些字段是真实的、哪些是占位值。
>
> **改造背景**：该功能原候选池为 `mock.js` 内 18 家人工虚构的招商线索（华为数字能源、宁德时代、小米智能制造等），既不在业务库、也不在数据仓库，评分由固定权重规则算出。2026-10-21 已整体替换为「数据仓库真实企业池 + 大模型评估」，虚构池已从代码中移除（引用清零）。

### 6.1 候选池口径（A 类：事实数据）

### 6.2 推荐流程与模型职责边界

| 步骤 | 实现 |
|---|---|
| 1. 取候选 | 按「推荐次数升序 + 注册资本降序」取 144 家，再按国标二级行业分散（同行业最多 2 家），得 12 家送模型 |
| 2. 组装上下文 | 庆阳 6 大重点招商产业方向 + 区位与算力枢纽信息 + 12 家候选企业逐条明细（行业 / 注册资本 / 所在地 / 经营范围节选） |
| 3. 模型任务 | 输出 JSON：总体判断（summary）+ 最多 5 条推荐（id / 契合度分 / 2 条理由 / 接洽建议） |
| 4. 后端校验 | id 必须落在候选列表内（列表外的 id 直接丢弃）；分数 clamp 到 60–98；去重 |
| 5. 落库 | `AiAnalysis`（`type = project_recommend`，含 payload、延迟毫秒、操作人） |
| 6. 轮转 | 被推荐企业的 `recommended` 计数 +1，下次优先取未被推荐过的企业，避免每批推同一批 |

**降级路径**：大模型不可用或输出非法 JSON 时**不抛错**——按注册资本排序取前 N 家，契合度固定 70 分，理由退化为「省份+城市+行业+注册资本」的规则描述，`degraded=true`、置信度记 0。界面照常出结果，但**此时的分数不具备任何研判含义**，需在演示或汇报时说明。

可信度界定：

| 内容 | 性质 | 可否对外引用 |
|---|---|---|
| 企业名称、信用代码、所在地、注册资本、成立年份、国标行业 | **A 类**，工商公示原值 | ✅ 可（注明取自数据仓库及查询时点） |
| 契合度评分（60–98） | **模型判断**，无固定公式、非量化测算 | ⚠️ 仅供内部排序参考；不得表述为「评估得分」或「评分模型产出」 |
| 推荐理由 / 接洽建议 / 总体判断 | **模型生成文本**，基于上述 A 类字段推断 | ⚠️ 仅供初访前参考，须人工核实 |

### 6.3 「确认纳入招商项目」后的字段真实性

点击「确认纳入」会把推荐企业写入企业库（轻量档案）并创建招商项目（线索对接阶段）。**该环节有 6 个字段是占位值，不是该企业的真实工商信息**：

| 字段 | 实际值 | 性质 |
|---|---|---|
| 企业名称 | 推荐企业真实名称 | ✅ A 类 |
| 统一社会信用代码 | `待补充（新引进建档）` | ❌ 占位（未回填候选池中的真实代码） |
| 法定代表人 | 空 | ❌ 未取 |
| 注册资本 | 投资额 × 0.25 | ❌ **派生值，且小于该企业真实注册资本**（投资额暂以真实注册资本占位，此处再乘 0.25） |
| 所属区县 | 固定「西峰区」（`district=xf`） | ❌ 占位。外省企业并无庆阳辖区归属；列表另存「省份+城市」文本，与区县字段不一致 |
| 产业归属 | 回落默认产业「软件与信息技术」 | ❌ 占位（国标二级行业名称与系统内 12 个招商产业 key 不匹配，代码回落第一个） |
| 投资额 / 项目金额 | 真实注册资本 | ⚠️ 占位（外省企业无投资意向数据，待初访后更新） |
| 就业 / 营收 / 税收 | 0 / — / — | ❌ 未知，未做推算（按「不凑数」原则留空而非估算） |
| 项目进度 | 8–13% 随机 | ❌ 演示值 |
| 项目风险等级 | 固定「正常 / 蓝」 | ❌ 默认值，非风险评估结论 |

⚠️ **纳入后的企业档案不得作为该企业的真实档案使用。** 招商专员完成初访、拿到投资意向与工商材料后，应整档替换为真实数据；对外汇报前也必须先完成这一步。

### 6.4 当前实现边界（不掩盖）

1. **未排除已在库企业**：候选池（外省企业）与 88 家庆阳样本库无交集，但同一家候选企业可能被重复推荐、重复纳入项目。目前仅靠 `recommended` 计数轮转降低概率，无硬去重。
2. **未做失信 / 高风险筛查**：界面思考动画文案写了「排除已在库企业，筛除高风险失信主体」，**实际未实现**——推荐环节不查司法、失信、经营异常数据。
3. **思考动画文案已过时**：界面仍显示「权重分配：投资强度 30% · 产业契合度 25% · 企业实力 20% · 就业带动 15% · 税收贡献 10%」。该权重属已被废弃的规则打分器，现由大模型综合判断，**不存在固定权重**。
4. **候选池是快照不是实时**：企业存续状态、注册资本变更不会自动同步。刷新需重新执行 Doris 导出 + `npm run seed`；`seed` 会清空重建该表，`recommended` 轮转计数一并归零。
5. **落库置信度是固定值**：`AiAnalysis.confidence` 成功时固定写 85，**不是**模型返回的置信度（模型不返回该字段）。
6. **分数绝对值不可跨批次比较**：每批候选企业不同，模型对分数标定不严格可比，只能用于同批次内排序。

## 九、数据更新

- 数据快照：`server/prisma/real-fixtures.json`（`generatedAt` 精确到秒）
- 服务启动时比对 `generatedAt`，不一致才重新导入；一致则跳过
- 进程内调度（`services/dailySync.ts`，每 30 分钟检查一次）：仅当 `generatedAt` 变化时重建，**不做无条件每日重建**——`seedDemoData` 会清空全部业务表，无条件重建会抹掉用户在系统内新建的任务 / 项目 / 政策
- ⚠️ **没有任何进程自动"拉取"新数据**：快照由人工离线执行 `tools/gen_real_fixtures.py` 生成。上述调度只负责"发现新快照 → 导入"，不等于自动取数。真实的日级自动取数尚未实现（原 Hermes cron `0 2 * * *` 在容器环境从未执行过）
- 备份：每天 03:00 进程内自动 `VACUUM INTO` 快照，保留 14 份，见 `services/backupScheduler.ts` / `tools/backup_db.mjs` / `tools/restore_db.mjs`
- **招商候选池（第六章）独立维护**：来源 `data-import/prospects/prospects.csv`，需重新执行 Doris 导出后 `npm run seed` 才会更新；该过程会清空重建候选池并重置 `recommended` 轮转计数。它与 `real-fixtures.json` 无关联，`dailySync` 不会更新它
